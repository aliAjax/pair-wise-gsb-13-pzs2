# 加油站班次交接对账

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 领域逻辑验证：`npm run verify`

离线优先的班次交接对账前端：交接单、油枪读数、收款流水三处合一，断网照常补录，
网络恢复后合并两端记录。数据保存在浏览器 localStorage（站内账本 + 模拟云端账本两个命名空间）。

## 核心行为

- **离线续作**：交接单、读数、收款、油价变更全部先写本地并入待传队列，恢复后一键同步。
- **两端合并**：按修订号（`rev` / `syncedRev`）检出“两端各有改动”。仅一端改动直接合并；
  两端都改时，站内已复核值不被迟到副本覆盖，两版都保留进冲突区，等站长在「同步中心」拍板。
- **油价重算**：油价变更后，未复核交接单的销售额按新价自动重算并入待传队列；已复核的锁定不动。
- **幂等重放**：每笔收款/每个操作都带幂等键，云端已应用过的操作重放直接成功、不再入账，
  上传失败（含“已应用但确认丢失”）保留待传内容并可重试，重放不会多出收款流水。
- **同一口径**：列表、汇总指标、CSV 导出全部派生自同一份 `buildReconRows` 结果，
  对账状态（待复核/已复核/有差异/有冲突）与收入（收款合计）处处一致。

## 代码结构

```
src/
  domain/        纯函数领域层（可独立验证）
    types.ts       实体与枚举
    reconcile.ts   销量/销售额/对账状态/汇总
    pricing.ts     生效油价与未复核重算
    merge.ts       两端合并、冲突留档、流水幂等并集
    exporter.ts    CSV 导出（与列表同源）
  store/
    persistence.ts localStorage 持久化与种子数据
    cloud.ts       模拟云端：幂等应用、丢确认故障、对端直改
    sync.ts        待传队列推送（失败保留）与拉回合并
    shiftStore.ts  Pinia store，界面动作入口
  components/    交接对账 / 收款流水 / 油价与重算 / 同步中心
scripts/verify.ts  领域行为验证（T1–T8）
```

## 演示建议

1. 「同步中心」点 **模拟断网**，补录一张交接单和一笔收款 → 待传队列 +2。
2. 勾选 **模拟上传丢确认** 后同步 → 上传失败、队列保留；取消勾选再同步 → 日志出现“重放去重”，云端流水不重复。
3. 用 **模拟对端改动** 改一张已复核班次的销售额，同时站内有未上传改动 → 同步后出现冲突卡片，站内已复核值保持权威，两版等站长核对。
4. 「油价与重算」改价 → 未复核交接单销售额自动重算，已复核班次金额不变。
