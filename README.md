# 加油站班次交接对账

- 行业：石油
- 技术栈：Vue3、Vite、TypeScript、Pinia、Element Plus
- 启动：`npm install && npm run dev`
- 构建：`npm run build`
- 测试：`npm test`（核心逻辑单测 + 端到端场景）

针对换班常断网的场景，把**班次交接单、油枪读数、收款流水**三处补录接成一套可离线续作的交接对账：

## 离线续作与合并

- 断网时三类录入照常进行，先落本地并进入**待传队列**；网络恢复（点"恢复网络"）后自动合并双端记录。
- 中心端用另一个 localStorage 命名空间模拟（`dfwlfront-7-shift-server-v1`），"模拟中心端改动"可复现另一终端离线补录的场景。

## 冲突：已复核不被迟到副本覆盖

- 同一班次双端各有改动、或站内已复核而中心端推来迟到副本时：**站内已复核值保持生效不被覆盖**，两版并存标记"冲突待核"，等站长在卡片内对比后选用站内版/中心版。
- 双端均未复核时暂取较新一版生效，同样留两版待核对；核对前该班次不再自动上传，避免覆盖中心端另一版。
- 双端离线改到同一版本号但内容不同时，中心端拒收并交由合并流程判冲突。

## 油价重算

- 发布新油价后，**未复核**交接单按新价立即重算销售额并打"已按新油价重算"标记；已复核/有差异班次金额锁定不变。

## 上传失败与幂等

- 勾选"模拟上传失败"复现请求到达但响应丢失：待传内容保留并记重试次数，恢复后点"立即同步/重试"。
- 每笔收款带客户端幂等键，重放在中心端只入一笔流水；交接单按版本 upsert，旧版本重放直接忽略。

## 同源对账

- 列表、顶部指标、班次汇总、导出 CSV 全部取自同一 `reconRows` 视图模型，对账状态与收入数字一致。

## 目录

- `src/lib/recon.ts` —— 合并/冲突、幂等入账、油价重算、对账视图模型等纯函数（可单测）
- `src/store.ts` —— Pinia：本地库 + 模拟中心端 + 待传队列 + 同步引擎
- `src/components/` —— 录入面板、交接单列表（含冲突双版核对）、同步面板
- `scripts/recon.test.mjs` —— 核心逻辑单测；`scripts/store.e2e.ts` —— 断网→合并→冲突→重试→重算端到端场景
